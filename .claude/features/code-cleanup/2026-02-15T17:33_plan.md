## Component Architecture

### DebugPanel Widget

```
DebugPanel (StatelessWidget)
  Constructor params:
    - heading: double
    - pitch: double
    - skyFraction: double
    - isCalibrated: bool
    - altitudeLevel: AltitudeLevel
    - windData: WindData
    - currentFps: double
    - currentParticleCount: int
    - viewMode: ViewMode
    - showPanel: bool
    - onTogglePanel: VoidCallback
    - onToggleViewMode: VoidCallback
    - onRecalibrate: VoidCallback

  build() returns:
    Stack(
      toggle button (always visible),
      if (showPanel) panel body (conditionally visible),
    )
```

The widget receives all values as read-only params and all mutations as callbacks. This mirrors how `AltitudeSlider`, `InfoBar`, and `CompassWidget` work in this codebase.

### Opacity Helper (particle_overlay.dart)

```dart
/// Calculates particle opacity from age using a sine curve.
/// Returns 0.0 at age=0, peaks at ~1.0 around age=0.5, returns to 0.0 at age=1.0.
static double _particleOpacity(double age) {
  return sin(age * 3.14159).clamp(0.0, 1.0);
}
```

Called from both `_paintDots()` and `_paintStreamlines()` in place of the inline `sin(p.age * 3.14159).clamp(0.0, 1.0)` expression.

## Implementation Notes

### Decisions
1. **DebugPanel includes toggle button** -- Keeps all debug UI in one widget. The Positioned wrapper for the toggle stays in ARViewScreen since it needs `MediaQuery.of(context).padding.top`.
2. **Remove all debugPrint from fake_wind_service.dart entirely** -- Do not wrap in `kDebugMode`. The wind data is visible in the debug panel. These were missed during P2A-001 performance optimization and fire at 20Hz.
3. **Static helper for opacity, not a Particle getter** -- Avoids adding fields to the hot Particle class (2000 instances). The static method is allocation-free.
4. **Remove parallaxFactor variable entirely** -- Dead code with an `ignore` comment is worse than no code. The getter still exists on `AltitudeLevel` if ever needed again.

### Patterns
- Follow existing `StatelessWidget` pattern (see `CompassWidget`, `InfoBar`)
- Follow existing import conventions (relative imports within lib/)
- No `kDebugMode` wrapping needed for items being removed (they are noise, not diagnostics)

### Trade-offs
- Not adding unit tests for `DebugPanel` widget -- existing integration tests in `ar_view_screen_test.dart` already verify toggle behavior and text content. Adding isolated widget tests would require mocking all 12 constructor params for marginal benefit.

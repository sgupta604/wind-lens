#### Item 4: Remove deprecated unused constant from auto_calibrating_sky_detector.dart
- **Status:** VERIFIED with caveat - test references it
- **File:** `/workspace/wind_lens/lib/services/sky_detection/auto_calibrating_sky_detector.dart`
- **Lines:** 98-99
- **Code:**

- **Test reference:** The test at `/workspace/wind_lens/test/services/sky_detection/auto_calibrating_sky_detector_test.dart` line 125-129 still references `AutoCalibratingSkyDetector.sampleRegionBottom` (with an `// ignore: deprecated_member_use_from_same_package` comment).
- **Fix:** Remove the constant AND remove the test that references it (the test just verifies a deprecated constant equals 0.4, which has no value).

#### Item 5: Replace custom debugPrint function in fake_wind_service.dart
- **Status:** VERIFIED - still applicable
- **File:** `/workspace/wind_lens/lib/services/fake_wind_service.dart`
- **Lines:** 101-108
- **Code:**
  ```dart
  /// Debug print function (only prints in debug mode).
  void debugPrint(String message) {
    assert(() {
      // ignore: avoid_print
      print(message);
      return true;
    }());
  }
  ```
- **Problem:** This file defines its own `debugPrint` function that shadows Flutter's built-in `debugPrint` from `foundation.dart`. Flutter's built-in already only prints in debug mode, so this custom function is redundant.
- **Impact:** The file calls `debugPrint()` on lines 48-49 and 94-95 (in `getWind()` and `getWindForAltitude()`). These calls would switch to Flutter's built-in `debugPrint` after removing the custom function.
- **Fix:** Remove the custom function (lines 101-108), add `import 'package:flutter/foundation.dart';` to get Flutter's built-in `debugPrint`.
- **Performance note:** These `debugPrint` calls fire on every wind data fetch (driven by compass 20Hz updates), so they fire ~20 times per second. Consider wrapping them in `if (kDebugMode)` or removing them entirely, similar to item 2. The performance optimization feature (P2A-001) previously removed excessive debugPrint calls for FPS improvement. These may have been re-introduced or missed.

#### Item 6: Consolidate duplicate opacity calculation in particle_overlay.dart
- **Status:** VERIFIED - still applicable
- **File:** `/workspace/wind_lens/lib/widgets/particle_overlay.dart`
- **Lines:** 489 and 530
- **Identical code in both locations:**
  ```dart
  final baseOpacity = sin(p.age * 3.14159).clamp(0.0, 1.0);
  ```
- **Context:** Line 489 is in `_paintDots()`, line 530 is in `_paintStreamlines()`. Both methods compute the same opacity from particle age.
- **Approach options:**
  1. Extract to a static helper method on `ParticleOverlayPainter` (e.g., `_particleOpacity(double age)`)
  2. Add an `opacity` getter to the `Particle` model itself
  3. Pre-compute opacity in the `_onTick` loop and store on the particle
- **Recommendation:** Option 1 (static helper on the painter) is simplest and avoids adding fields to the hot `Particle` class. Option 3 would be a micro-optimization (compute once per particle per frame instead of once per paint method) but adds a field to Particle.
- **Best approach:** Static helper method, since this is in the painter which is already performance-sensitive and adding a field to Particle could have memory implications for 2000 particles.

## 1. Architecture Overview

Wind Dome is a full-screen 3D wind visualization rendered over a live map. The user's GPS
position anchors a half-ellipsoid dome containing 2000 animated wind particles driven by
real OGC EDR forecast data (3 altitude layers, 72 hours). The map uses flutter_map with
CartoDB Dark Matter tiles. A forecast slider enables instant time travel through the 72-hour
GFS forecast without additional network calls.

### Layer Stack

```
WindDomeScreen (ConsumerStatefulWidget)
|
+-- Stack
    |
    +-- flutter_map (fills screen)
    |   CartoDB Dark Matter tiles, zoom 14, locked to GPS
    |   No user pan/zoom -- map follows stablePositionProvider
    |
    +-- Positioned.fill
        +-- GestureDetector (drag-to-orbit)
            +-- CustomPaint
                +-- DomePainter (CustomPainter)
                    +-- drawDomeWireframe()
                    +-- drawParticles()
                    +-- drawUserMarker()
    |
    +-- Positioned (bottom)
        +-- DomeForecastSlider (0-72h)
    |
    +-- Positioned (top)
        +-- DomeInfoBar (wind speed, altitude, live/forecast badge)
```

### Data Flow

```
stablePositionProvider (existing, Layer 3)
        |
        v
domeWindProfileProvider (NEW, FutureProvider)
        |  Calls DomeWindFetcher.fetch(lat, lng)
        |  DomeWindFetcher calls WindApiClient.fetchPointWindSeries() x3 pressure levels
        |  Returns DomeWindProfile (72 DomeWindFields, each with 3 DomeWindLayers)
        |
        v
hoursAheadProvider (NEW, StateProvider<int>, default 0)
        |
        v
currentDomeWindFieldProvider (NEW, Provider<DomeWindField?>)
        |  profile.fieldAt(hoursAhead) -- no network, instant
        |
        v
WindDomeScreen reads currentDomeWindFieldProvider in Ticker tick loop
        |  For each DomeParticle: field.sample(x, y, z) -> WindVector
        |  Particle position += wind * renderScale * speedScale * dt
        |  frameCounter.value++ triggers DomePainter repaint
        v
DomePainter projects 3D -> 2D via Matrix4 perspective, draws trails
```

## 4. Data Model Details

### 4.1 DomeWindLayer (plain class, NOT Freezed)

```dart
class DomeWindLayer {
  final double altitudeMeters;  // Real-world altitude (10, 1500, 3000)
  final double u;               // East component m/s (from EDR directly)
  final double v;               // North component m/s (from EDR directly)
  const DomeWindLayer({required this.altitudeMeters, required this.u, required this.v});
}
```

### 4.2 DomeWindField (plain class, sample() is hot-path)

```dart
class DomeWindField {
  final DateTime validTime;
  final List<DomeWindLayer> layers;  // 3 entries, sorted by altitude ascending

  /// Vertical interpolation. x and z are unused in MVP (uniform horizontal).
  /// y is render-space height [0, DOME_H_RENDER].
  WindVector sample(double x, double y, double z) {
    // Map y to altitude fraction, interpolate between layers
  }
}
```

Key: `sample()` interpolates u/v components (NOT speed/direction) to avoid 0/360 wraparound.

### 4.3 DomeWindProfile (plain class)

```dart
class DomeWindProfile {
  final List<DomeWindField> hourly;  // 72+ entries
  final DateTime fetchedAt;
  final double lat, lng;

  DomeWindField fieldAt(int hoursAhead) =>
      hourly[hoursAhead.clamp(0, hourly.length - 1)];
}
```

### 4.4 DomeParticle (mutable, NOT Freezed)

```dart
class DomeParticle {
  double x, y, z;
  final List<double> trailX, trailY, trailZ;  // Ring buffer, fixed size
  int trailHead = 0;
  int trailCount = 0;

  void tick(DomeWindField field, double dt, double domeR, double domeH) { ... }
  void respawn(Random rng, double domeR, double domeH) { ... }
  static bool insideDome(double x, double y, double z, double r, double h) { ... }
}
```

Note: Use parallel arrays (trailX/trailY/trailZ) instead of List<Vector3> to avoid
object allocation in the hot path. Ring buffer with fixed capacity = TRAIL_LENGTH.

### 4.5 Altitude Layer Mapping

| Layer | Pressure | API param | Altitude (m) | Dome normY |
|-------|----------|-----------|-------------|-----------|
| 0 | Surface (10m AGL) | pressureLevel=0 | 10 | 0.006 |
| 1 | 850 hPa | pressureLevel=850 | 1500 | 0.83 |
| 2 | 700 hPa | pressureLevel=700 | 3000 | Above dome (interp boundary) |

Dome height = 1800m. Layers 0-1 are inside the dome. Layer 2 (700 hPa, ~3000m) is the
upper interpolation boundary — close enough to dome apex that particles near the top are
driven by realistic ~3km-altitude wind, not jetstream-level 300hPa wind at 9000m.

## 5. WindApiClient Extension

### 5.1 New method: fetchPointWindSeries()

```dart
/// Fetches a time series of wind vectors at a single point.
///
/// Returns a list of (DateTime, double u, double v) tuples for [hours]
/// forecast hours. Tries Shyft first, falls back to Folkweather.
///
/// On both-APIs-fail, returns an empty list.
Future<List<({DateTime time, double u, double v})>> fetchPointWindSeries({
  required double lat,
  required double lng,
  required int pressureLevel,
  int hours = 72,
}) async { ... }
```

The datetime range is `{now_utc}/{now_plus_hours_utc}` instead of a single instant.
The CoverageJSON response has `t.values` with multiple entries and `u-component-of-wind.values`
with matching count.

### 5.2 Parsing changes

Shyft time-series: `coverages[]` still has separate U/V coverages, but each coverage's
values array has N entries matching the N timestamps in `t.values`. Parse by iterating
the time axis and zipping with the value arrays.

Folkweather time-series: Single Coverage with `ranges.UGRD.values` and `ranges.VGRD.values`
arrays matching `domain.axes.t.values`.

### 5.3 Datetime range format

```
Shyft:       &datetime=2026-02-27T12:00:00Z/2026-03-02T12:00:00Z
Folkweather: &datetime=2026-02-27T12:00:00Z/2026-03-02T12:00:00Z
```

Same format for both APIs per OGC EDR spec.

## 7. 3D Projection

Matrix4 perspective projection using vector_math (already a dependency):

```dart
Matrix4 _buildCameraMatrix(double theta, double phi, double camDist) {
  final m = Matrix4.identity();
  m.rotateY(theta);    // Azimuth (horizontal drag)
  m.rotateX(phi);      // Elevation (vertical drag)
  m.translate(Vector3(0, -DOME_H_RENDER * 0.25, -camDist));
  return m;
}

Offset _project(Vector3 v, Matrix4 cam, Size size) {
  final p = cam.transform3(v);
  final fov = 600.0;
  final scale = fov / (fov + p.z.abs() + 1e-6);
  return Offset(
    size.width / 2 + p.x * scale,
    size.height * 0.45 - p.y * scale,
  );
}
```

Camera orbit: horizontal drag changes theta, vertical drag changes phi.
phi clamped to [0.15, pi*0.46] to prevent flipping.
Default view: theta=pi/6, phi=pi/2.8 (looking down ~50 degrees).

**Map bearing sync:** When theta changes, rotate the map bearing in sync via
`_mapController.rotate(-theta * 180 / pi)`. This keeps the dome's "north" aligned
with the map's north at all times.

## 8. Component Architecture

### 8.1 Widget Tree

```
WindDomeScreen (ConsumerStatefulWidget)
  State:
    - List<DomeParticle> _particles (owned by State, survives rebuilds)
    - Ticker _ticker (animation loop)
    - PerformanceManager _perfManager
    - ValueNotifier<int> _frameCounter (triggers repaint)
    - double _theta, _phi (camera orbit angles)
    - MapController _mapController (flutter_map)
  |
  +-- Stack
      +-- FlutterMap
      |     controller: _mapController
      |     options: MapOptions(
      |       initialCenter: userLatLng
      |       initialZoom: 14
      |       interactionOptions: none (locked)
      |     )
      |     children: [TileLayer(urlTemplate: CartoDB Dark Matter)]
      |
      +-- GestureDetector
      |     onPanUpdate -> update theta/phi
      |     child: ValueListenableBuilder<int>
      |       valueListenable: _frameCounter
      |       builder: CustomPaint(
      |         painter: DomePainter(
      |           particles: _particles,
      |           theta: _theta, phi: _phi,
      |           domeR: DOME_R_RENDER, domeH: DOME_H_RENDER,
      |           ...
      |         )
      |       )
      |
      +-- Positioned(bottom)
      |     DomeForecastSlider(
      |       hoursAhead: ref.watch(hoursAheadProvider)
      |       onChanged: (h) => ref.read(hoursAheadProvider.notifier).state = h
      |     )
      |
      +-- Positioned(top)
            DomeInfoBar(
              windField: ref.watch(currentDomeWindFieldProvider)
              hoursAhead: ref.watch(hoursAheadProvider)
            )
```

### 8.2 State Management

- **Particle state**: Owned by _HomeScreenState equivalent (WindDomeScreen State).
  Mutable list passed by reference to DomePainter. Painter reads but does not own.
  This is the CustomPainter State Survival Pattern from CLAUDE.md.

- **Animation**: Ticker calls tick() on each particle, then increments frameCounter.
  ValueListenableBuilder wraps CustomPaint so only the paint area rebuilds, not the
  whole widget tree. Zero Riverpod rebuilds from animation.

- **Camera orbit**: theta/phi stored as plain doubles on State. Updated via setState()
  from GestureDetector.onPanUpdate. This triggers a rebuild of only the GestureDetector
  subtree (which includes the CustomPaint). Map bearing syncs with theta so map north
  stays aligned with dome north during orbit.

- **Forecast hour**: hoursAheadProvider (StateProvider<int>). DomeForecastSlider writes
  it, currentDomeWindFieldProvider reads it. Changing the slider does NOT trigger a
  network call -- it just indexes into the cached 72-hour array.

- **Wind data**: domeWindProfileProvider (FutureProvider) auto-refetches when
  stablePositionProvider changes. The profile is cached for 10 minutes by DomeWindFetcher.

## 10. Implementation Notes

### 10.1 Key Decisions

1. **flutter_map v7 (not v6)**: The spec says ^6.0.0 but the current Flutter SDK
   is 3.x with Dart ^3.10.7. flutter_map v7 is the latest stable and uses latlong2 ^0.9.1.
   Use ^7.0.0 unless version conflicts arise, then fall back to ^6.0.0.

2. **Parallel array trail buffer**: Use `List<double>` for trailX/trailY/trailZ instead of
   `List<Vector3>` to avoid object allocation. Ring buffer pattern with head pointer and count.
   Max capacity = TRAIL_LENGTH (10). This is the hot-path optimization required by CLAUDE.md.

3. **DomeWindFetcher as separate class (not a WindDataSource)**: DomeWindFetcher does NOT
   implement the existing WindDataSource interface because it returns a 72-hour profile
   (not a single WindData). It wraps WindApiClient directly, similar to OgcEdrWindDataSource.
   **Cache is static** so it survives fetcher recreation across provider dispose/rebuild cycles
   (same principle as avoiding the instance-field cache bug from CachedWindDataSource).

4. **Map bearing rotates with dome orbit**: When the user drags to orbit the dome (changing
   theta), the map's bearing rotates in sync via MapController.rotate(). This keeps the dome's
   "north" aligned with the map's north at all times. Without this, the map grid stays north-up
   while the dome spins, which is visually confusing. flutter_map's MapController supports
   bearing rotation natively.

5. **Dome radius = 800m** (per spec Open Question resolution, not 1200m from earlier in spec).
   DOME_H_METERS = 1800m. Aspect ratio: dome is wider than tall when rendered.

6. **Camera distance**: Auto-calculated from DOME_R_RENDER to ensure dome fits on screen
   with some margin. camDist = DOME_R_RENDER * 2.5 (tunable).

### 10.2 Patterns Followed

- ConsumerStatefulWidget with TickerProviderStateMixin (same as ARViewScreen, HomeScreen)
- ValueNotifier<int> frameCounter for repaint trigger (same as ParticleOverlay sensorNotifiers)
- Constructor-injected http.Client on WindApiClient (existing)
- FakeWindApiClient for test isolation (existing pattern)
- PerformanceManager for adaptive particle count (existing)
- Mutable particle state owned by StatefulWidget State (CustomPainter State Survival Pattern)

### 10.3 Trade-offs

- **No horizontal wind variation in MVP**: All particles at the same altitude get the same
  wind vector regardless of x/z position. This is meteorologically acceptable within 800m.
  Phase 2 adds a 3x3 grid for horizontal shear.

- **Artificial vertical wind**: w = 0.002 + (normY * 0.004) per frame. Not physically measured
  but prevents particles from piling at dome walls. Artistic approximation.

- **Map zoom fixed at 14**: No pinch-to-zoom. At zoom 14, the 800m dome radius maps to a
  clearly visible circle on screen. Phase 3 adds zoom.

### 10.4 Risk Mitigation

- **flutter_map version conflict**: If flutter_map ^7.0.0 conflicts with other deps, try ^6.0.0.
  The API surface we use (TileLayer, MapController, MapOptions) is stable across versions.

- **Shyft time-series response format unknown**: The spec assumes the CoverageJSON time-series
  format has t.values as an array. If Shyft returns a different structure for range datetime
  queries, we may need to adjust parsing. Mitigation: test with real API response first, have
  Folkweather fallback ready.

- **Performance on older devices**: 2000 particles + map tiles + 3D projection + trail
  rendering could be heavy. PerformanceManager will auto-reduce to 1000 particles.
  DomePainter skips glow pass (unlike ParticleOverlay) to save GPU -- single-pass white lines.

- No horizontal wind grid (3x3 sampling) -- Phase 2
- No pinch-to-zoom camera -- Phase 3
- No adjustable dome radius -- Phase 3
- No compass-aligned dome (north always stays north) -- Phase 3

### Patterns to Follow

**Service Pattern (from CompassService):**
```dart
class LocationService {
  // Stream controller (broadcast)
  final _controller = StreamController<LocationData>.broadcast();

  // Public API
  Stream<LocationData> get stream => _controller.stream;
  double get latitude => _latitude;
  double get longitude => _longitude;
  bool get hasPermission => _hasPermission;

  // Lifecycle
  Future<void> start() async { ... }  // Note: async for permission request
  void dispose() { ... }

  // Test helpers
  @visibleForTesting
  void setPosition(double lat, double lon) { ... }
}
```

**Key difference from CompassService:** Location permission requires an explicit async request before accessing GPS. CompassService's `start()` is synchronous. LocationService's `start()` must be `async`.

**Model Pattern (from CompassData):**
```dart
class LocationData {
  final double latitude;
  final double longitude;
  final double accuracy;
  final DateTime timestamp;

  const LocationData({
    required this.latitude,
    required this.longitude,
    required this.accuracy,
    required this.timestamp,
  });
}
```

**Debug Panel Pattern:** The DebugPanel is a stateless widget that takes all data via constructor parameters. Adding lat/lon means adding two new fields and passing them from ARViewScreen.

**ARViewScreen Wiring Pattern:**
```dart
// In initState:
_locationService = LocationService();
_locationService.start();  // async, fire-and-forget is OK for startup
_locationSubscription = _locationService.stream.listen(_onLocationUpdate);

// In dispose:
_locationSubscription?.cancel();
_locationService.dispose();

// Handler:
void _onLocationUpdate(LocationData data) {
  setState(() {
    _latitude = data.latitude;
    _longitude = data.longitude;
  });
}
```

## Package Analysis: geolocator

### Recommendation: Use `geolocator` ^14.0.2

**Why geolocator:**
- Most popular Flutter GPS package (published by Baseflow)
- Cross-platform: iOS (CLLocationManager), Android (FusedLocationProviderClient)
- Built-in permission handling: `checkPermission()`, `requestPermission()`, `isLocationServiceEnabled()`
- Stream API: `getPositionStream()` for continuous updates
- One-shot API: `getCurrentPosition()` for single fetch
- Handles platform differences internally
- Active maintenance (latest version 14.0.2)

**Key API methods we need:**
1. `Geolocator.checkPermission()` -> `LocationPermission` enum
2. `Geolocator.requestPermission()` -> `LocationPermission` enum
3. `Geolocator.isLocationServiceEnabled()` -> `bool`
4. `Geolocator.getCurrentPosition()` -> `Position` (one-shot)
5. `Geolocator.getPositionStream()` -> `Stream<Position>` (continuous)

**LocationSettings for our use case:**
```dart
const locationSettings = LocationSettings(
  accuracy: LocationAccuracy.medium,  // ~100m is fine, battery-friendly
  distanceFilter: 50,                 // Only update when moved 50+ meters
);
```

We only need coarse accuracy (~10m per roadmap, ~100m is even fine since terrain doesn't change that fast). Using `LocationAccuracy.medium` and a 50m distance filter keeps battery usage low.

**Compatibility:**
- Dart SDK ^3.10.7 (our project) -- compatible
- Android compileSdk 35 (flutter.compileSdkVersion) -- compatible with geolocator 14
- Android minSdk 24 -- compatible (geolocator requires 16+)
- iOS 14.0+ -- compatible

**Alternatives considered and rejected:**
- `location` package: Less popular, overlapping API, no advantage
- Direct platform channels: Unnecessary complexity for a well-solved problem
- `gps` package: Not as well-maintained

## Open Questions

- [x] Q1: Should we use `geolocator` or `location` package?
  - Resolution: `geolocator` -- more popular, better maintained, cleaner permission API, recommended by roadmap.

- [x] Q2: What accuracy level do we need?
  - Resolution: `LocationAccuracy.medium` (~100m). The roadmap says ~10m is fine. For terrain detection, even 100m is adequate since terrain profiles don't change significantly over short distances. Medium accuracy saves battery.

- [x] Q3: How often should we get location updates?
  - Resolution: Use `distanceFilter: 50` (meters). Only update when user moves 50+ meters. For initial position, use `getCurrentPosition()` once on start. For ongoing, use `getPositionStream()` with distance filter.

- [x] Q4: Do we need to modify Info.plist or AndroidManifest.xml?
  - Resolution: NO. Both already have location permission strings configured from the original project setup. No platform file changes needed.

- [x] Q5: How should permission denial be handled?
  - Resolution: Set `_hasPermission = false`, log a warning, do not crash. The rest of the app (HSV sky detection, fake wind data, compass) continues to work. Downstream features (HeyWhatsThat, real wind) will check `locationService.hasPermission` before attempting to use GPS data.

- [x] Q6: Should LocationService's `start()` be async?
  - Resolution: Yes. Unlike CompassService which accesses sensors directly, LocationService needs to `await requestPermission()` before accessing GPS. The `start()` method should be `Future<void>`. ARViewScreen can call it without awaiting (fire-and-forget at startup) and handle the async result via the stream.

- [x] Q7: What data model should we use?
  - Resolution: Create a simple `LocationData` model (lat, lon, accuracy, timestamp) analogous to `CompassData`. Do not expose geolocator's `Position` class directly to keep the service boundary clean.

## Recommended Approach

### Implementation Strategy

Follow the exact same pattern as CompassService. Create a LocationService that:

1. Wraps the `geolocator` package behind a clean interface
2. Provides a broadcast stream of `LocationData` updates
3. Handles permissions internally with graceful degradation
4. Exposes `@visibleForTesting` helpers for unit tests
5. Integrates into ARViewScreen the same way CompassService does

### Order of Work

1. **Add geolocator dependency** to `pubspec.yaml`, run `flutter pub get`
2. **Create LocationData model** at `lib/models/location_data.dart`
3. **Create LocationService** at `lib/services/location_service.dart` with:
   - `start()` (async -- checks/requests permission, starts stream)
   - `dispose()` (cancels subscription, closes controller)
   - `stream` getter (broadcast Stream<LocationData>)
   - `latitude`, `longitude`, `hasPermission` getters
   - `@visibleForTesting setPosition()` helper
4. **Add lat/lon to DebugPanel** -- new constructor parameters + display row
5. **Wire into ARViewScreen** -- create, start, listen, dispose, pass to DebugPanel
6. **Write tests** for LocationData model, LocationService logic, and DebugPanel with lat/lon

### What to Defer (Not MVP Critical)
- Background location updates (only need while-in-use)
- Location accuracy indicator in UI (can add later if needed)
- Altitude from GPS (geolocator provides it, but not needed for P2B-001)
- Reverse geocoding / address display (not in scope)

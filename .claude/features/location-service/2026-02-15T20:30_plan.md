## Architecture Overview

LocationService follows the exact same pattern as CompassService: a broadcast StreamController, lifecycle methods (`start()`/`dispose()`), direct getters for current values, and `@visibleForTesting` helpers for unit testing without platform channels.

The key difference from CompassService is that `start()` is async because it must request GPS permission before accessing position data.

```
                           +-------------------+
                           |  ARViewScreen     |
                           |                   |
                           |  initState():     |
                           |    _locService    |
                           |      .start()     |
                           |    _locSub =      |
                           |      .stream      |
                           |      .listen()    |
                           |                   |
                           |  dispose():       |
                           |    _locSub.cancel |
                           |    _locService    |
                           |      .dispose()   |
                           +--------+----------+
                                    |
                         stream: Stream<LocationData>
                                    |
                           +--------+----------+
                           | LocationService   |
                           |                   |
                           | + start()  async  |
                           | + dispose()       |
                           | + stream          |
                           | + latitude        |
                           | + longitude       |
                           | + hasPermission   |
                           |                   |
                           | @visibleForTesting|
                           | + setPosition()   |
                           +--------+----------+
                                    |
                            geolocator package
                                    |
                     +--------------+--------------+
                     |                             |
              iOS CLLocation              Android Fused
              Manager                     Location Provider
```

### Data Flow

```
GPS Hardware → geolocator.getPositionStream() → LocationService._onPosition()
    → creates LocationData(lat, lon, accuracy, timestamp)
    → adds to _controller (broadcast StreamController)
    → ARViewScreen._onLocationUpdate() receives via stream
    → setState() updates _latitude, _longitude
    → passes to DebugPanel as constructor params
```

## Component Specifications

### LocationData Model

```dart
// lib/models/location_data.dart
class LocationData {
  final double latitude;
  final double longitude;
  final double accuracy;   // meters
  final DateTime timestamp;

  const LocationData({
    required this.latitude,
    required this.longitude,
    required this.accuracy,
    required this.timestamp,
  });
}
```

Simple immutable data class. Mirrors the pattern of `CompassData` (two required fields). Adds `accuracy` and `timestamp` for downstream consumers (HeyWhatsThat, real wind data). No methods, no serialization -- keep it minimal.

### LocationService

```dart
// lib/services/location_service.dart
class LocationService {
  // --- Internal state ---
  double _latitude = 0;
  double _longitude = 0;
  bool _hasPermission = false;
  StreamSubscription<Position>? _positionSub;
  final _controller = StreamController<LocationData>.broadcast();

  // --- Public API ---
  Stream<LocationData> get stream => _controller.stream;
  double get latitude => _latitude;
  double get longitude => _longitude;
  bool get hasPermission => _hasPermission;

  // --- Lifecycle ---
  Future<void> start() async {
    // 1. Check if location services enabled
    // 2. Check/request permission
    // 3. If granted: get initial position, start stream
    // 4. If denied: set _hasPermission = false, log warning, return
  }

  void dispose() {
    _positionSub?.cancel();
    _controller.close();
  }

  // --- Test helpers ---
  @visibleForTesting
  void setPosition(double lat, double lon) {
    _latitude = lat;
    _longitude = lon;
    _hasPermission = true;
    _controller.add(LocationData(
      latitude: lat,
      longitude: lon,
      accuracy: 0,
      timestamp: DateTime.now(),
    ));
  }
}
```

**Key design decisions:**

1. **`start()` is `Future<void>`** -- unlike CompassService's synchronous `start()`, because permission request is async. ARViewScreen calls it fire-and-forget.
2. **`hasPermission` getter** -- downstream features (HeyWhatsThat, real wind) check this before using GPS data.
3. **`setPosition()` test helper** -- sets lat/lon, sets hasPermission=true, emits to stream. Single method for test setup.
4. **LocationSettings** -- `LocationAccuracy.medium` + `distanceFilter: 50` for battery efficiency. GPS only updates when user moves 50+ meters.
5. **No timer** -- unlike CompassService which needs 20Hz smoothing, LocationService just forwards geolocator stream events. No smoothing needed for GPS.

### DebugPanel Changes

Add two optional `double?` parameters for lat/lon. Display as a new row when values are non-null. Using nullable types means existing code that does not pass lat/lon still compiles without changes.


### ARViewScreen Changes

Wire LocationService alongside CompassService:

```dart
// New fields:
late LocationService _locationService;
StreamSubscription<LocationData>? _locationSubscription;
double? _latitude;
double? _longitude;

// In initState (after compass setup):
_locationService = LocationService();
_locationService.start();  // async, fire-and-forget
_locationSubscription = _locationService.stream.listen(_onLocationUpdate);

// In dispose (before compass disposal):
_locationSubscription?.cancel();
_locationService.dispose();

// New handler:
void _onLocationUpdate(LocationData data) {
  setState(() {
    _latitude = data.latitude;
    _longitude = data.longitude;
  });
}

// In DebugPanel constructor call:
latitude: _latitude,
longitude: _longitude,
```

## Implementation Notes

### Decisions

1. **Nullable lat/lon in DebugPanel** -- Use `double?` instead of `double` with a default of 0. This way, DebugPanel shows "GPS: ..." only when data is available. Avoids misleading "GPS: 0.0000, 0.0000" before first fix.

2. **Fire-and-forget start()** -- ARViewScreen does not await `_locationService.start()`. The async permission flow happens in the background, and the stream delivers data when ready. This keeps `initState()` synchronous (Flutter requirement).

3. **No error stream** -- If permission is denied, `hasPermission` is false and the stream simply never emits. Downstream code checks `hasPermission` before using GPS. No error events, no exceptions -- graceful silence.

4. **geolocator not mocked in tests** -- We use `@visibleForTesting setPosition()` to bypass geolocator entirely in unit tests. The geolocator package uses platform channels that are not available in the test environment. This matches the CompassService pattern where `simulateMagnetometerEvent()` bypasses `sensors_plus`.

### Patterns

- Same service pattern as CompassService
- Same model pattern as CompassData
- Same DebugPanel extension pattern (add params, add row)
- Same ARViewScreen wiring pattern (field, initState, dispose, handler)

### Trade-offs

- **Medium accuracy vs high accuracy:** Using `LocationAccuracy.medium` (~100m) saves battery. For terrain detection (P2B-004), even 100m is fine because horizon profiles do not change significantly over short distances. Can upgrade to high accuracy later if needed.
- **distanceFilter: 50m** -- Means no updates when standing still. For P2B-001 this is fine. If downstream features need more frequent updates, the filter can be reduced.

## Non-Goals

- Background location updates (only need while-in-use)
- GPS altitude reading (geolocator provides it but not needed for P2B-001)
- Reverse geocoding or address display
- Location accuracy indicator in the UI
- Animated location permission dialog (standard OS dialog is sufficient)
- Caching last known location across app restarts (can add in P2B-003 if needed)

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| Permission denied | `hasPermission = false`, stream never emits, app continues with HSV detection |
| Location services disabled | Check `isLocationServiceEnabled()` first, log warning if disabled |
| geolocator version conflict | Pin to `^14.0.2`, test `flutter pub get` in Task 1.1 |
| Tests break from new DebugPanel params | Use nullable params with no default -- existing callers unaffected |
| ARViewScreen test breakage | LocationService wiring is internal; existing tests render without GPS data |

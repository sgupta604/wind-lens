# Research: wind-dome-rendering

## Summary

The wind dome rendering layer needs a complete rewrite. The current implementation incorrectly mixes flutter_map coordinate space with dome rendering — particles are placed at real-world lat/lng coordinates and projected through flutter_map's tile projection, producing a flat 2D scatter instead of a 3D dome. A working prototype exists in React/THREE.js (`wind-dome.jsx`) that defines the exact coordinate system, camera model, dome geometry, and particle physics needed.

## The Problem

**Current architecture (broken):**
- Particles exist at real-world lat/lng coordinates
- Positions are projected to screen via flutter_map's tile projection
- Result: flat 2D circle of dots on the map with no depth, no wireframe, no 3D perspective
- The `_buildCameraMatrix` is either not applied or overridden by map projection

**Required architecture:**
- flutter_map = background wallpaper only (dark tiles centered on GPS)
- CustomPainter = completely self-contained 3D scene in its own coordinate space
- Dome coordinates: x, y, z in render units centered at (0,0,0) — NO lat/lng, NO meters
- Camera: spherical orbit (phi, theta) with perspective projection
- The two layers share ONE thing: GPS position tells flutter_map where to center tiles

## Reference Implementation

**File:** `.claude/features/wind-dome/wind-dome.jsx` (446 lines, React/THREE.js)

This is the working prototype that produces the target visual (see `prototype.png`). Key parameters and patterns to port:

### Coordinate System
```
DOME_R = 18    // dome radius in render units
DOME_H = 14    // dome height (half-ellipsoid)
```
All geometry lives in this space. No real-world units.

### Camera Model (spherical orbit)
```javascript
let phi = Math.PI / 2.8;    // ~50° from zenith (oblique view)
let theta = Math.PI / 6;     // initial azimuth
const CAM_R = DOME_R * 2.8;  // camera distance = 50.4

camera.position.set(
  CAM_R * Math.sin(phi) * Math.sin(theta),
  CAM_R * Math.cos(phi),
  CAM_R * Math.sin(phi) * Math.cos(theta)
);
camera.lookAt(0, DOME_H * 0.2, 0);  // look slightly above center
```

### Dome Wireframe
- **Latitude rings:** 8 rings, each at normY = i/8, radius = DOME_R * sqrt(1 - normY²), opacity 0.06-0.10
- **Longitude lines:** 16 meridians, opacity 0.05
- **Footprint circle:** on ground plane, opacity 0.5
- **Vertical axis:** from user marker to dome apex, opacity 0.08

### User Position Marker
- Inner dot (r=0.7, white, at y=0.06)
- Outer ring (r=1.1-1.5, white, pulsing opacity 0.6±0.3)
- Accuracy halo (r=2.5-2.8, white, opacity 0.08-0.14)

### Particle System
- 2000 particles, 10-segment trails
- **Spawn:** rejection sampling inside half-ellipsoid: (x²+z²)/R² + y²/H² <= 1
- **Wind sampling:** vertical interpolation between altitude layers, velocity = speed * 0.012
- **Movement:** vx/vz from wind, vy = 0.002 + (y/H)*0.003 (gentle upward drift)
- **Containment:** respawn when outside dome (with 2% margin)
- **Trail rendering:** LineSegments with per-vertex color, brightness = altBright * trailFade * speedFactor
  - altBright = 0.4 + (y/DOME_H) * 0.6
  - trailFade = 1.0 - (seg/TRAIL_LENGTH) * 0.93
  - speedFactor = 0.5 + speedNorm * 0.5

### Gesture Handling
- **1-finger drag:** theta -= dx * 0.007, phi = clamp(phi - dy * 0.005, 0.15, pi*0.46)
- **Pinch zoom:** adjust CAM_R (camera distance)
- **2-finger vertical drag:** tilt phi between pi/2 (top-down) and pi/2.8 (oblique)

## What to Rewrite

### `dome_painter.dart` — FULL REWRITE
Port the prototype's rendering to CustomPainter:
1. Own perspective projection (not flutter_map)
2. Camera position from spherical coords (phi, theta, camR)
3. Project3D: apply camera transform, perspective divide, center on canvas
4. Draw order: ground plane → footprint circle → wireframe (lat rings + meridians) → particles → user marker
5. Particles as line segments with per-trail-point alpha
6. All coordinates in dome-local render units

### `wind_dome_screen.dart` — GESTURE + LAYOUT REWRITE
1. flutter_map as background layer (no interaction)
2. CustomPainter overlay (Positioned.fill)
3. Listener widget for multi-touch: Map<int, Offset> _activePointers
4. Particle state owned by StatefulWidget (CustomPainter state survival pattern)
5. AnimationController for continuous repaint

### `dome_particle.dart` — PHYSICS REWRITE
1. Coordinates: x, y, z in dome render units (not meters, not lat/lng)
2. Spawn: rejection sampling inside half-ellipsoid
3. Wind: sample from DomeWindField, apply as vx/vz with scale factor
4. Vertical drift: vy = 0.002 + (y/DOME_H) * 0.003
5. Containment: respawn when outside ellipsoid
6. Trail: history array of (x, y, z) positions

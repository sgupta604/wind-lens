## Architecture Overview

### Current State

```
main.dart
  -> ARViewScreen (god widget, 311 lines)
       OWNS: CompassService, FakeWindService, LocationService, AutoCalibratingSkyDetector
       OWNS: 15 state variables, 6 stream subscriptions
       PASSES: everything via constructor params to 6 child widgets
```

Data flow: `Hardware -> Service -> StreamSubscription -> setState() -> child widgets`

### Target State

```
main.dart
  -> ProviderScope
       -> WindLensApp
            -> ARViewScreen (ConsumerWidget, ~80 lines)
                 READS: sceneStateProvider, sensorNotifiersProvider
                 RENDERS: CameraView, ParticleOverlay, CompassWidget, etc.

Provider Graph:
  Layer 1: sensorServiceProvider -> gpsPositionProvider, rawSensorProvider
  Layer 2: stablePositionProvider (debounced >100m)
  Layer 3: horizonProfileProvider, windDataProvider (auto-refetch on position change)
  Layer 4: skyDetectorProvider, skyMaskProvider
  Layer 5: sceneStateProvider (composes all, fallback for horizon/sky, blocks on position/wind)
  Layer 6: selectedAltitudeProvider, detectionModeProvider (user state)
  Sidecar: SensorNotifiers (ValueNotifier<double> for heading/pitch at sensor rate)
```

Data flow: `Hardware -> SensorService -> Stream<T> -> Riverpod provider -> Widget rebuild (infrequent) + ValueNotifier (60Hz render)`

### SkyMask Rename Strategy

The name "SkyMask" is needed for the new Freezed data class. The existing `SkyMask` abstract interface must be renamed. However, we must be careful because the particle overlay and many tests reference it.

**Approach:** Rename the existing `SkyMask` interface to `SkyDetectorInterface` in Phase 1. In Phase 2, when we restructure directories and the particle overlay is refactored, the new `SkyDetector` abstract class in `lib/core/services/sky_detector.dart` replaces it. The `SkyDetectorInterface` is a temporary name used only within Phase 1 to avoid collision while both the old interface and new Freezed `SkyMask` data class coexist.

Actually, simpler approach: The existing `SkyMask` interface can stay named `SkyMask` in its current location during Phase 1. The new Freezed data class goes into `lib/core/models/sky_mask_data.dart` as `SkyMaskData`. In Phase 2, when we do the directory restructure, we rename the old interface to align with SPEC-001 naming. This avoids touching every file that references `SkyMask` in Phase 1.

**Decision: Use `SkyMaskData` for the Freezed class in Phase 1. Defer the SkyMask->SkyDetector rename to Phase 2 when the directory restructure happens anyway.**

### WindData Redesign

The new Freezed WindData keeps u/v as primary fields (per research Q2 resolution):

```dart
@freezed
class WindData with _$WindData {
  const WindData._();  // Private constructor for custom methods

  const factory WindData({
    required double uComponent,       // eastward m/s
    required double vComponent,       // northward m/s
    @Default(0.0) double gustSpeed,   // m/s
    required AltitudeLevel altitude,  // enum instead of raw meters
    required DateTime timestamp,
  }) = _WindData;

  factory WindData.fromJson(Map<String, dynamic> json) => _$WindDataFromJson(json);

  // Computed getters (same as current WindData)
  double get speed => sqrt(uComponent * uComponent + vComponent * vComponent);
  double get directionRadians => atan2(-uComponent, -vComponent);
  double get directionDegrees => (directionRadians * 180 / pi + 360) % 360;

  // Convenience factory for mock data
  factory WindData.fromSpeedDirection({
    required double speed,
    required double directionDegrees,
    double gustSpeed = 0.0,
    required AltitudeLevel altitude,
    DateTime? timestamp,
  }) {
    final dirRad = directionDegrees * pi / 180;
    return WindData(
      uComponent: -speed * sin(dirRad),
      vComponent: -speed * cos(dirRad),
      gustSpeed: gustSpeed,
      altitude: altitude,
      timestamp: timestamp ?? DateTime.now(),
    );
  }

  static WindData zero() => WindData(
    uComponent: 0, vComponent: 0,
    altitude: AltitudeLevel.surface,
    timestamp: DateTime.now(),
  );
}
```

**Key change:** `altitude` field changes from `double` (raw meters) to `AltitudeLevel` (enum). This affects `FakeWindService` and all tests referencing `wind.altitude`. The old code used `altitude: 10.0` or `altitude: level.metersAGL`. Now it will use `altitude: AltitudeLevel.surface`.

### Wrapper Implementations

Wrappers are thin delegation layers. They own the existing service instance and translate between old and new APIs.

**DeviceSensorService** wraps CompassService + LocationService:
- Owns a CompassService and LocationService internally
- Maps `CompassData` stream -> `SensorState` stream (adds timestamp)
- Maps `LocationData` stream -> `PositionData` stream (altitude: 0.0 placeholder in Phase 1)
- `pause()`: cancels subscriptions, `resume()`: re-subscribes
- **NOTE:** `altitude: 0.0` is a known placeholder. geolocator's `Position.altitude` IS available but current `LocationData` doesn't expose it. Wire it in during Phase 2 when LocationData is deleted. This matters for P2B-006 (OGC EDR) which needs observer altitude for surface vs. pressure level wind queries. Record explicitly in DECISIONS.md.

**MockWindDataSource** wraps FakeWindService:
- `getWind(position, altitude)` -> delegates to `FakeWindService.getWindForAltitude(altitude)`
- Returns `Future.value(...)` (synchronous wrap in Future)
- `isSimulated: true`

**MockHorizonProvider** (new, no wrapping):
- Returns `HorizonProfile.flat(lat, lng)` -- 0-degree elevation at all bearings
- For testing and indoor use

**HsvSkyDetector** wraps AutoCalibratingSkyDetector:
- `detect(frame, sensors, horizon)`:
  1. Calls `_detector.updatePitch(sensors.pitch)`
  2. Calls `_detector.processFrame(frame)`
  3. Extracts cached mask into `SkyMaskData(width, height, pixels, method: .hsv)`
- `name: 'HSV Auto-Calibrating'`

### Backward Compatibility Strategy

During Phase 1, existing code (ARViewScreen, widgets, tests) still uses the old classes directly. The wrappers exist alongside them. This means:

1. Old `LocationData` stays alive -- `lib/models/location_data.dart` remains unchanged
2. Old `CompassData` stays alive -- `lib/models/compass_data.dart` remains unchanged
3. Old `WindData` is REPLACED by Freezed version (same file path, same field names, same API)
4. Old `SkyMask` interface stays alive in its current location
5. Old services (`CompassService`, `LocationService`, `FakeWindService`) stay alive
6. New wrappers (`DeviceSensorService`, etc.) own instances of the old services

Phase 2 will migrate consumers to use the new types and delete the old files.

**Exception: WindData must be replaced in-place** because the Freezed version changes the `altitude` field type from `double` to `AltitudeLevel`. This is the riskiest step in Phase 1, so it is split into two sub-tasks:
- **Task 1.4a:** Create the new Freezed WindData model and get it compiling with build_runner. Write tests for the new model. Old WindData remains untouched.
- **Task 1.4b:** Migrate consumers file by file (FakeWindService, tests, widgets, screen). Read each file, update it, verify compilation, then move to the next. Do NOT try to hold the entire changeset in memory at once.

## Implementation Notes

### Key Decisions (to be recorded in DECISIONS.md)

1. **WindData keeps u/v as primary fields.** Speed/direction are computed getters. Reason: OGC EDR returns u/v; particle physics uses u/v directly; storing speed/direction means unnecessary trig per particle per frame.

2. **WindData.altitude changes from double to AltitudeLevel enum.** This is a breaking change that touches FakeWindService, ParticleOverlay, tests. Worth it because altitude levels are an enum concept throughout the app, not arbitrary meter values.

3. **SkyMask interface NOT renamed in Phase 1.** The new Freezed data class is called `SkyMaskData` to avoid collision. The rename happens in Phase 2 during directory restructure.

4. **Old model classes (CompassData, LocationData) stay alive in Phase 1.** New Freezed models (SensorState, PositionData) exist alongside them. Old classes are deleted in Phase 2 when all consumers are migrated.

5. **CameraImage used directly in SkyDetector interface.** No CameraFrame wrapper -- adds no value right now. Can be abstracted later if needed.

6. **HSV and Particle NOT converted to Freezed.** HSV is in hot pixel loop. Particle is intentionally mutable (2000 mutations/frame). Both would be performance-killed by Freezed immutability.

7. **PerformanceManager stays as-is.** Pure logic class, no external dependencies, no need for interface.

8. **No Hive/Isar.** Phase 3 caching uses simple JSON file persistence via path_provider + dart:io.

9. **AltitudeLevel enum stays as plain enum with extension.** No Freezed needed.

### Patterns Established

- **Freezed models** in `lib/core/models/` with `part` directives for generated code
- **Service interfaces** in `lib/core/services/` as pure Dart abstract classes
- **Concrete implementations** in `lib/services/<category>/` wrapping existing code
- **Backward compatibility** via keeping old classes alive during transition
- **One model at a time** to catch build_runner issues early

### Trade-offs

| Decision | Benefit | Cost |
|----------|---------|------|
| u/v as primary WindData fields | No trig in particle loop, natural for OGC EDR | SPEC-001 deviation (spec uses speed/direction) |
| SkyMaskData name (not SkyMask) | Avoids collision, no rename cascade in Phase 1 | Temporary non-SPEC name, fixed in Phase 2 |
| Keep old classes alive | Zero test breakage for unchanged consumers | Code duplication during transition |
| CameraImage in interface | Simple, no abstraction overhead | Couples core interface to camera package |

| Too many files to change at once | One model at a time; run tests after each |

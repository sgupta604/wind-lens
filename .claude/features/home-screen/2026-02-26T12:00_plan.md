## Architecture Overview

The home screen is a new landing page that replaces the current direct-to-camera launch behavior. It reads from the existing Riverpod provider graph (no new providers, no new services) and presents wind data in a calm dashboard view. The user explicitly taps "Live AR" to enter the camera.

```
+------------------------------------------------------------------+
|                        HomeScreen                                |
|  ConsumerStatefulWidget + TickerProviderStateMixin               |
|                                                                  |
|  +------------------------------------------------------------+ |
|  |  HomeTopBar                                                 | |
|  |  - Logo: "ShyftLens" (Bebas Neue) + "ATMOSPHERIC AR" sub   | |
|  |  - Live AR button (white pill, pulsing red dot)             | |
|  +------------------------------------------------------------+ |
|  |  Divider (1px, #111111)                                     | |
|  +------------------------------------------------------------+ |
|  |  HomeWindRow (ConsumerWidget)                               | |
|  |  - Speed | Direction | Altitude                             | |
|  |  - Reads: sceneStateProvider, selectedAltitudeProvider       | |
|  +------------------------------------------------------------+ |
|  |  HomeTerrainSection (Expanded, fills remaining space)       | |
|  |  Stack:                                                     | |
|  |    [0] HomeGridPainter (faint grid lines)                   | |
|  |    [1] HomeTerrainPainter (bezier silhouette)               | |
|  |    [2] HomeParticlePainter (80 animated particles)          | |
|  |    [3] HomeAltitudeRail (right edge, absolute)              | |
|  |    [4] HomeCompassBar (bottom edge, absolute)               | |
|  +------------------------------------------------------------+ |
|  |  HomeLayerToggles                                           | |
|  |  - [Particles] [Pressure] [Terrain] [Clouds]               | |
|  +------------------------------------------------------------+ |
+------------------------------------------------------------------+
```

### Data Flow

```
Existing Riverpod Graph               HomeScreen Widgets
========================               =================

sceneStateProvider ----+---> HomeWindRow (speed, direction)
                       |
                       +---> HomeParticlePainter (wind bias - future)

selectedAltitudeProvider --> HomeWindRow (altitude label)
                         --> HomeAltitudeRail (active tick)

sensorNotifiersProvider ---> HomeCompassBar
  .headingNotifier           (ValueListenableBuilder, no setState)
```

No new providers are created. No new services. The home screen is a pure consumer of the existing graph.

### Navigation

```
HomeScreen ---[tap "Live AR"]---> Navigator.push(ARViewScreen)
```

## Component Specifications

### HomeScreen (`home_screen.dart`)

- `ConsumerStatefulWidget` with `TickerProviderStateMixin`
- Owns `AnimationController _particleController` (duration: 1s, repeat)
- Scaffold with black background, no AppBar
- SafeArea wrapping Column:
  1. `HomeTopBar`
  2. `Divider` (1px, `#111111`, horizontal margin 28)
  3. `HomeWindRow`
  4. `HomeTerrainSection` (Expanded, receives `_particleController`)
  5. `HomeLayerToggles`
- Reads: `sceneStateProvider` (passed to terrain section for future wind-influenced particles)

### HomeTopBar (`home_top_bar.dart`)

- `StatefulWidget` (needs own `AnimationController` for pulsing red dot, or receives one from parent)
  - Decision: Own `SingleTickerProviderStateMixin` for the pulse animation (isolated, simple)
- Row: left = logo column, right = Live AR button
- Logo: "ShyftLens" in Bebas Neue 32sp white, letter-spacing 2
- Subtitle: "ATMOSPHERIC AR" in DM Mono 9sp, `#444444`, letter-spacing 3
- Live AR button: white pill (`BorderRadius.circular(100)`), contains:
  - Pulsing red dot: 8px circle, `AnimatedBuilder` opacity 0.5-1.0, duration 1.4s
  - "LIVE AR" text: DM Mono, black, uppercase, letter-spacing 0.15em
  - Padding: horizontal 18, vertical 10
- `onTap`: calls callback passed from HomeScreen
- Semantics: `label: 'Open live AR camera view'`

### HomeWindRow (`home_wind_row.dart`)

- `ConsumerWidget` (needs ref.watch for providers)
- Reads: `sceneStateProvider`, `selectedAltitudeProvider`
- Three equal-width columns in a `Row` with `Expanded`:
  - Speed: label "SPEED", value `sceneState?.wind.speed.toStringAsFixed(1)` or "--", unit "mph"
  - Direction: label "DIRECTION", value `degreesToCardinal(sceneState?.wind.directionDegrees)` or "--", unit "bearing XXX deg"
  - Altitude: label "ALTITUDE", value from `selectedAltitude` display name mapped to feet, unit "ft AGL"
- Values: Bebas Neue 28sp white
- Labels: DM Mono 8sp `#333333` uppercase letter-spacing 0.25em
- Units: DM Mono 9sp `#444444` letter-spacing 0.15em
- Columns separated by `VerticalDivider(color: Color(0xFF111111))`
- Padding: 18 vertical, 28 horizontal
- Wind values semantics: `label: 'Wind speed X miles per hour'`

#### Altitude Display Mapping

The spec shows "2.4K" for altitude display. Map `AltitudeLevel` to feet:
- surface (10m): "33" ft
- midLevel (1,500m): "4.9K" ft
- jetStream (10,500m): "34.4K" ft

Use `metersAGL * 3.28084` and format with K suffix for values >= 1000.

### HomeTerrainSection (`home_terrain_section.dart`)

- Stateless widget receiving `AnimationController` and optional `WindData?`
- Expanded in parent Column, contains a `Stack`:
  1. `CustomPaint(painter: _HomeGridPainter())` -- faint grid lines
  2. `CustomPaint(painter: HomeTerrainPainter())` -- terrain silhouette
  3. `CustomPaint(painter: HomeParticlePainter(animation: controller))` -- particles
  4. `Positioned(right: 0, ...)` -> `HomeAltitudeRail`
  5. `Positioned(bottom: 14, ...)` -> `HomeCompassBar`

The grid painter is simple enough to be a private class inside `home_terrain_section.dart`:
- Lines: `rgba(255,255,255,0.025)`, 48px spacing, horizontal + vertical

### HomeTerrainPainter (`home_terrain_section.dart`, inline or separate)

- `CustomPainter` with `shouldRepaint => false` (static)
- Accepts `HorizonProfile? profile` for future swap-in
- If `profile == null`: hardcoded decorative bezier path from spec
- Fill color: `#1a1a1a` (dark charcoal)
- Ridge highlight: 1px stroke `#2e2e2e` along top edge
- Horizon line: 1px horizontal at `size.height * 0.65`, `rgba(255,255,255,0.10)`

### HomeParticlePainter (`home_particle_painter.dart`)

- `CustomPainter` with `repaint: animation` (the controller listenable)
- Contains `List<_HomeParticle>` (80 particles, initialized lazily on first paint)
- `_HomeParticle` is a private mutable class:
  - Fields: `x, y, vx, vy, life, maxLife, radius, waveOffset`
  - `List<Offset> trail` (last 20 positions)
- Spawn: left edge (95%) or right edge (5%)
- y: random in middle 70%
- vx: 0.5-1.6 px/frame, vy: +/-0.15 px/frame
- Sinusoidal wiggle: `vy += sin(waveOffset + x * 0.015) * 0.1`
- Life: 0 to maxLife (0.5-1.0), alpha = `sin(life/maxLife * pi) * 0.6`
- Trail: 20 positions, tapered opacity
- Paint: trail lines + head dot (white, varying alpha)
- Reset when life >= maxLife or x out of bounds

### HomeAltitudeRail (`home_altitude_rail.dart`)

- `ConsumerWidget` reading `selectedAltitudeProvider`
- 5 evenly spaced ticks:
  - "10,000 ft" (jetStream)
  - "7,500 ft" (inactive, no corresponding level -- visual only)
  - "4,900 ft" (midLevel) -- note: the spec says "2,400 ft" but that maps to midLevel at 1500m = ~4900ft. Use spec values literally: "10,000 ft", "7,500 ft", "2,400 ft", "1,000 ft", "Surface"
  - "1,000 ft" (inactive, visual only)
  - "Surface" (surface)
- Active tick (matching selectedAltitude): white text, white line (18px), triangle marker
- Inactive: `#282828` text, `#222222` line
- Font: DM Mono 8sp
- Tapping ticks with a real altitude level calls `ref.read(selectedAltitudeProvider.notifier).select(level)`
- Tapping decorative ticks (7,500 ft, 1,000 ft) does nothing

#### Altitude Rail Mapping

Only 3 of the 5 tick positions correspond to actual `AltitudeLevel` values:
| Label | AltitudeLevel | Tappable |
|-------|---------------|----------|
| 10,000 ft | jetStream | Yes |
| 7,500 ft | (none) | No |
| 2,400 ft | midLevel | Yes |
| 1,000 ft | (none) | No |
| Surface | surface | Yes |

### HomeCompassBar (`home_compass_bar.dart`)

- Stateless widget receiving `ValueNotifier<double> headingNotifier`
- 8 directions: N, NE, E, SE, S, SW, W, NW
- Uses `ValueListenableBuilder<double>` on `headingNotifier`
- Active direction (nearest to heading): `#666666` text
- Inactive: `#222222` text
- Font: DM Mono 9sp
- Positioned 14px from bottom, full width, 28px horizontal padding
- Nearest direction: `((heading + 22.5) % 360 / 45).floor()` maps to index 0-7

### HomeLayerToggles (`home_layer_toggles.dart`)

- Stateless widget (MVP: visual only, no state changes)
- 4 buttons in a Row with 8px gap:
  - "PARTICLES" -> on (white bg, black text)
  - "PRESSURE" -> dim (`#111` bg, `#222` border, `#555` text)
  - "TERRAIN" -> on (white bg, black text)
  - "CLOUDS" -> dim
- Font: DM Mono 9sp uppercase, letter-spacing 0.15em
- Border radius: 6
- Height: 38px
- Padding: 0 horizontal 28, 18 bottom

### wind_utils.dart (`core/utils/wind_utils.dart`)

```dart
String degreesToCardinal(double degrees) {
  const directions = ['N','NNE','NE','ENE','E','ESE','SE','SSE',
                       'S','SSW','SW','WSW','W','WNW','NW','NNW'];
  final index = ((degrees % 360) / 22.5).round() % 16;
  return directions[index];
}
```

## Implementation Notes

### Decisions

1. **App name in UI:** "ShyftLens" (not "WindLens"). The package name `wind_lens` remains unchanged. Only UI-facing text uses the new name.
2. **google_fonts vs bundled:** Use `google_fonts` package for simplicity. The app requires internet for wind data anyway, so font download is acceptable. If offline support becomes critical later, bundle fonts locally.
3. **HomeTopBar owns its pulse animation:** Rather than the HomeScreen owning two animation controllers, HomeTopBar gets its own `SingleTickerProviderStateMixin`. This keeps concerns separated.
4. **HomeWindRow as ConsumerWidget:** It needs direct access to `ref.watch(sceneStateProvider)` and `ref.watch(selectedAltitudeProvider)`. Making it a `ConsumerWidget` is cleaner than passing data down.
5. **HomeAltitudeRail as ConsumerWidget:** Same reasoning -- needs `ref.watch(selectedAltitudeProvider)` and `ref.read(selectedAltitudeProvider.notifier).select()`.
6. **Compass bar avoids Riverpod rebuild:** Uses `ValueListenableBuilder` directly on `headingNotifier`, matching the pattern used by `ParticleOverlay`.
7. **Grid painter is private:** `_HomeGridPainter` lives inside `home_terrain_section.dart` because it is trivial and only used there.
8. **HomeTerrainPainter lives in its own file or in terrain section:** Given the spec provides ~90 lines of path code, keeping it inside `home_terrain_section.dart` is acceptable since `shouldRepaint => false` means no complexity cost. But for testability of the future `HorizonProfile` swap-in, a separate file is better. Decision: keep inside `home_terrain_section.dart` as a non-private class `HomeTerrainPainter` so it can be referenced in tests if needed.

### Patterns

- Follow the `features/ar_view/` pattern: screen file at feature root, widgets in `widgets/` subdirectory
- Use `ConsumerWidget` (not `ConsumerStatefulWidget`) for widgets that only read providers
- Use `ConsumerStatefulWidget` only when local state or animation controllers are needed
- Use `pump()` not `pumpAndSettle()` in tests with animation controllers (they never settle)

### Trade-offs

- **80 particles on home screen vs 2000 in AR:** Home screen particles are decorative, not data-driven. 80 is enough for visual appeal without wasting battery.
- **Layer toggles visual-only:** Wiring to `detectionModeProvider` is deferred. This avoids scope creep and keeps the feature focused on the landing page.
- **Altitude rail labels are spec-literal:** The spec says "2,400 ft" for midLevel even though 1500m = 4921ft. Using the spec values creates a more aesthetically pleasing display. The exact values are secondary to the visual design intent.

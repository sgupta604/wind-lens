## Bug Summary

The compass widget works for approximately 1 second then freezes permanently. The dead zone check in `CompassService` is applied BEFORE smoothing updates, creating a convergence trap: once the smoothed heading is within 1.0 degree of the raw heading (~35 events at 50-100 Hz), the early return fires on every event, blocking both smoothing and stream emission forever.

The same bug affects pitch via `_onAccelerometerEvent` with a 2.0 degree dead zone.

## Root Cause

```
_onMagnetometerEvent flow (CURRENT - BUGGY):

  raw heading
      |
      v
  delta = raw - smoothed
      |
      v
  delta < deadZone? --YES--> return (BLOCKS smoothing + emission)
      |
      NO
      v
  apply smoothing
      |
      v
  emit update
```

The fix moves smoothing before the dead zone gate:

```
_onMagnetometerEvent flow (FIXED):

  raw heading
      |
      v
  delta = raw - smoothed
      |
      v
  apply smoothing  <-- ALWAYS runs
      |
      v
  delta < deadZone? --YES--> return (only suppresses emission)
      |
      NO
      v
  emit update
```

## Implementation Details

### Fix 1: `_onMagnetometerEvent` (lines 77-100)

Move `_smoothedHeading` update to BEFORE the dead zone check. The dead zone still suppresses emission but no longer blocks the smoothing filter.

**Before (buggy):**
```dart
if (delta.abs() < headingDeadZone) {
  return;  // blocks smoothing AND emission
}
_smoothedHeading = (_smoothedHeading + delta * smoothingFactor + 360) % 360;
_emitUpdate();
```

**After (fixed):**
```dart
_smoothedHeading = (_smoothedHeading + delta * smoothingFactor + 360) % 360;
if (delta.abs() < headingDeadZone) {
  return;  // only suppresses emission, smoothing already applied
}
_emitUpdate();
```

### Fix 2: `_onAccelerometerEvent` (lines 106-125)

Same pattern: move `_smoothedPitch` update before dead zone check.

**Before (buggy):**
```dart
if (delta.abs() < pitchDeadZone) {
  return;
}
_smoothedPitch += delta * smoothingFactor;
_emitUpdate();
```

**After (fixed):**
```dart
_smoothedPitch += delta * smoothingFactor;
if (delta.abs() < pitchDeadZone) {
  return;
}
_emitUpdate();
```

### Fix 3: `start()` error handling (lines 68-71)

Add `onError` handlers to prevent unhandled sensor errors from propagating.

```dart
void start() {
  _magnetometerSub = magnetometerEventStream().listen(
    _onMagnetometerEvent,
    onError: (error) {
      debugPrint('Magnetometer error: $error');
    },
  );
  _accelerometerSub = accelerometerEventStream().listen(
    _onAccelerometerEvent,
    onError: (error) {
      debugPrint('Accelerometer error: $error');
    },
  );
}
```

## Testing Strategy

### Approach: Make CompassService Testable

The existing tests cannot exercise the event handler methods because `start()` calls platform-specific `magnetometerEventStream()` and `accelerometerEventStream()`. To write proper regression tests, we need to call `_onMagnetometerEvent` and `_onAccelerometerEvent` directly.

**Options evaluated:**
1. **Make methods visibleForTesting** -- Cleanest. Add `@visibleForTesting` annotation and make methods public with underscored names.
2. **Inject stream factories** -- More refactoring than warranted for a bug fix.
3. **Test the algorithm in isolation** -- Already exists but missed the bug.

**Decision:** Use option 1. Add `@visibleForTesting` to expose `onMagnetometerEvent` and `onAccelerometerEvent` as public methods for testing. This allows tests to simulate sequential sensor events without platform channels.

Alternatively, if we want zero API surface change: create a `simulateMagnetometerEvent(double x, double y)` method with `@visibleForTesting`. This is slightly cleaner as it takes raw x/y values rather than requiring test code to construct `MagnetometerEvent` objects.

**Final decision:** Add `@visibleForTesting` test helper methods that accept raw sensor values, avoiding dependency on `MagnetometerEvent`/`AccelerometerEvent` constructors in tests.

## Implementation Notes

### Why the dead zone check order matters

The dead zone's purpose is to suppress jittery output emissions when the device is nearly stationary. It should NOT prevent the internal smoothing filter from tracking the actual sensor readings. When smoothing is blocked, the internal state diverges from reality, and recovery requires a large enough sensor jump to exceed the dead zone -- which may never happen during slow rotation.

### The fix preserves dead zone anti-jitter behavior

After the fix, the dead zone still prevents rapid small emissions. The only difference is that `_smoothedHeading` / `_smoothedPitch` continue to track the raw sensor values internally, so the compass is always ready to emit when a significant change occurs.

### Risk assessment

- **Risk:** Low. The change is a 2-line reorder in each of 2 methods.
- **Regression risk:** Low. Existing behavior for large heading changes is unchanged. The dead zone still suppresses small-change emissions.
- **Performance impact:** None. No new allocations, no new computation.

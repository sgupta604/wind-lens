# Feature Summary: real-wind-data (P2B-006)

## Overview

Replaced `MockWindDataSource` (synthetic sinusoidal wind) with `OgcEdrWindDataSource` that fetches real atmospheric wind data from OGC EDR weather APIs. The app now displays actual wind patterns at three altitude levels using live GFS and HRRR weather model data. Shyft is the primary API; Folkweather is the fallback. On dual-API failure, the app renders static (non-moving) particles instead of crashing.

## Status

**FINALIZED** — 2026-02-26. All 610 tests passing. Committed on branch `feature/wind-dome-homescreen`.

## Architecture

```
service_providers.dart
  windDataSourceProvider
    CachedWindDataSource (TTL=10min, existing)
      OgcEdrWindDataSource (new, implements WindDataSource)
        WindApiClient (new, shared HTTP + parsing layer)
          Shyft API (primary) -> Folkweather API (fallback) -> (0,0) zero wind
```

The `WindApiClient` is a shared service layer designed for reuse:
- AR view (point queries via `OgcEdrWindDataSource.getWind()`)
- Future Wind Dome feature (grid queries via `WindApiClient.fetchWindGrid()`)

## Architecture Decisions

### 1. Point queries for WindDataSource, area queries for Wind Dome
`OgcEdrWindDataSource.getWind()` uses `fetchPointWind()` — one HTTP call per altitude level for the user's GPS coordinates. `fetchWindGrid()` is implemented in `WindApiClient` but reserved for the future Wind Dome feature, which needs a full spatial wind field.

### 2. 300 hPa for jet stream (not 250)
Both APIs reliably support 300 hPa. Shyft 250 hPa availability is inconsistent. 300 hPa (~9km) is close enough to the 10.5km jet stream altitude.

### 3. Datetime pinning on all Shyft queries
All Shyft requests include `datetime=<nearest_hour_utc>`. Without it, Shyft returns 180+ forecast timesteps instead of the current time slice.

### 4. Plain classes for WindVector/WindField
NOT Freezed. Hot-path bilinear interpolation for Wind Dome would suffer Freezed overhead. Follows project pattern: Freezed for domain models, plain Dart for service-layer hot-path types.

### 5. Constructor-injected http.Client for testability
Tests use `package:http/testing.dart` `MockClient` with canned JSON responses. No mockito needed. Follows the existing `@visibleForTesting` injection pattern used throughout the project.

### 6. Folkweather longitude normalization
Folkweather returns longitudes in 0-360 format. All Folkweather parsers convert to -180/180 range for consistent coordinates.

### 7. Graceful degradation to zero wind
On dual API failure or malformed JSON, returns `(0.0, 0.0, 'none')`. App renders static particles (no motion) instead of crashing. The camera feed and sky detection continue unaffected.

## API Routing

| Altitude | Shyft collection | Folkweather collection |
|----------|-----------------|----------------------|
| Surface (10m) | `GFS_height-above-ground_10` (no z param) | `hrrr-height-agl?z=10` |
| Mid-level (850 hPa) | `GFS_isobaric?z=850` | `hrrr-isobaric?z=850` |
| Jet stream (300 hPa) | `GFS_isobaric?z=300` | `gfs-isobaric-latest?z=300` |

## Key Constants

- `WindApiConstants.shyftApiKey` — Shyft API key (compile-time constant in `wind_api_constants.dart`)
- HTTP timeout: 12 seconds (generous for cellular networks)
- Cache TTL: 10 minutes (from existing `CachedWindDataSource`)
- Cache key: rounded lat/lng (2 decimal places) + `AltitudeLevel`

## Architecture Overview

This feature replaces `MockWindDataSource` with a real OGC EDR wind data service using a dual-API fallback strategy (Shyft primary, Folkweather fallback). The architecture separates the shared HTTP/parsing layer from the `WindDataSource` adapter so the same API client can be reused by the future Wind Dome feature.

```
                    +---------------------+
                    |  service_providers  |
                    |  .dart              |
                    +----------+----------+
                               |
                    windDataSourceProvider
                               |
                    +----------v----------+
                    | CachedWindDataSource |  (already exists, reused)
                    | ttl: 10 min         |
                    +----------+----------+
                               |  delegate
                    +----------v----------+
                    | OgcEdrWindDataSource |  implements WindDataSource
                    | - getWind()         |  extracts center point from grid
                    | - isSimulated=false |
                    +----------+----------+
                               |  uses
                    +----------v----------+
                    |   WindApiClient      |  shared HTTP + parsing layer
                    |                     |
                    | + fetchWindGrid()   |  returns WindField
                    | + fetchPointWind()  |  returns (u, v) tuple
                    |                     |
                    | Shyft primary -->   |
                    | Folkweather fallback|
                    +----------+----------+
                               |
                    +----------v----------+
                    |  WindField           |  grid of wind vectors
                    |  WindVector          |  single u/v point
                    |  (plain classes)     |  NOT Freezed (hot-path)
                    +---------------------+

Future consumer (Wind Dome):

    DomeWindFetcher ---uses---> WindApiClient.fetchWindGrid()
                                returns full WindField with
                                bilinear interpolation
```

### Data Flow

```
GPS fix --> stablePositionProvider (debounce >100m)
        --> windDataProvider (watches stablePosition + selectedAltitude)
        --> windDataSourceProvider
        --> CachedWindDataSource (check TTL cache)
            --> OgcEdrWindDataSource.getWind()
                --> WindApiClient.fetchPointWind(lat, lng, altitude)
                    --> Try Shyft position query (12s timeout)
                    --> On failure: Try Folkweather position query
                    --> On both fail: return (0.0, 0.0) for graceful degradation
                --> Construct WindData(u, v, altitude, timestamp)
        <-- WindData flows back through provider graph
        --> ParticleOverlay reads wind for particle physics
```

### API Request Flow

```
AltitudeLevel.surface  --> Shyft: GFS_height-above-ground_10/position (no z param, datetime pinned)
                       --> Folk:  hrrr-height-agl/position?z=10

AltitudeLevel.midLevel --> Shyft: GFS_isobaric/position?z=850
                       --> Folk:  hrrr-isobaric/position?z=850

AltitudeLevel.jetStream --> Shyft: GFS_isobaric/position?z=300
                        --> Folk:  gfs-isobaric-latest/position?z=300
```

### 2. WindVector and WindField (`wind_models.dart`)

Plain mutable classes adapted from the research companion `wind_data_service.dart`. NOT Freezed because WindField is used in hot-path interpolation for the future Wind Dome feature.

```dart
/// Wind vector at a point (U/V in m/s).
class WindVector {
  final double u;
  final double v;
  const WindVector({required this.u, required this.v});
  static const zero = WindVector(u: 0, v: 0);
  double get speed => sqrt(u * u + v * v);
}

/// Grid of wind vectors with bilinear interpolation.
class WindField {
  final List<double> xs;   // longitudes sorted ascending
  final List<double> ys;   // latitudes sorted ascending
  final List<double> us;   // U components, row-major [row * width + col]
  final List<double> vs;   // V components
  final String source;
  final DateTime fetchedAt;

  // ... getAt(), interpolate(), interpolateAtCoord(), centerWind()
}
```

Key addition vs. research code: `centerWind()` method returns the WindVector closest to the grid center, used by `OgcEdrWindDataSource.getWind()` for the single-point extraction.

### 3. WindApiClient (`wind_api_client.dart`)

The shared HTTP + parsing layer. Accepts an `http.Client` in the constructor for testability.

```dart
/// Shared API client for OGC EDR wind data.
///
/// Handles HTTP requests and response parsing for both Shyft and
/// Folkweather APIs. Designed as a reusable service:
///
/// - OgcEdrWindDataSource uses fetchPointWind() for single-point queries
/// - [Future] DomeWindFetcher will use fetchWindGrid() for spatial grids
class WindApiClient {
  final http.Client _client;

  WindApiClient({http.Client? client}) : _client = client ?? http.Client();

  /// Fetch wind at a single point. Tries Shyft, falls back to Folkweather.
  /// Returns (u, v) in m/s. On both-APIs-fail, returns (0.0, 0.0).
  Future<(double u, double v, String source)> fetchPointWind({
    required double lat,
    required double lng,
    required int pressureLevel,  // 0 = surface
  }) async { ... }

  /// Fetch wind grid in a bounding box. For future Wind Dome use.
  Future<WindField> fetchWindGrid({
    required double lat,
    required double lng,
    double radiusKm = 40,
    required int pressureLevel,
  }) async { ... }

  // --- Shyft methods ---
  Future<(double, double)> _fetchShyftPoint(double lat, double lng, int level) async { ... }
  (double, double) _parseShyftPositionResponse(Map<String, dynamic> json) { ... }

  // --- Folkweather methods ---
  Future<(double, double)> _fetchFolkPoint(double lat, double lng, int level) async { ... }
  (double, double) _parseFolkPositionResponse(Map<String, dynamic> json) { ... }

  // --- Area query methods (for fetchWindGrid) ---
  Future<WindField> _fetchShyftArea(String encodedPoly, int level) async { ... }
  WindField _parseShyftMultiPoint(Map<String, dynamic> json, String source) { ... }
  Future<WindField> _fetchFolkArea(String encodedPoly, int level) async { ... }
  WindField _parseFolkArea(Map<String, dynamic> json, String source) { ... }

  // --- Helpers ---
  String _nearestHourUtc() { ... }  // for Shyft datetime pinning
  String _folkCollection(int level) { ... }  // route to HRRR vs GFS
  void dispose() { _client.close(); }
}
```

**Key design decisions:**

1. **Constructor-injected `http.Client`** -- Tests pass a custom client that returns canned JSON. No mockito needed. Follows the `@visibleForTesting` pattern used elsewhere in the project.

2. **Point queries for WindDataSource, area queries for Wind Dome** -- The `fetchPointWind()` method uses position queries (one HTTP call per altitude). The `fetchWindGrid()` method uses area queries and returns a full `WindField`. Both share the same parsing logic.

3. **Graceful degradation** -- If both APIs fail, `fetchPointWind()` returns `(0.0, 0.0, 'none')` instead of throwing. The caller constructs `WindData.zero()`.

4. **Shyft datetime pinning** -- Always includes `&datetime=<nearest_hour_utc>` on ALL queries (isobaric AND surface) to avoid getting 180+ forecast timesteps. Surface collection behavior is untested without datetime — include it defensively.

5. **Folkweather longitude normalization** -- Converts 0-360 to -180/180 range.

### 4. OgcEdrWindDataSource (`ogc_edr_wind_source.dart`)

Thin adapter that implements `WindDataSource` using `WindApiClient`.

```dart
/// Real wind data source using OGC EDR APIs.
///
/// Maps AltitudeLevel to pressure levels and delegates HTTP
/// calls to WindApiClient. Returns a single WindData point
/// for the user's GPS location.
class OgcEdrWindDataSource implements WindDataSource {
  final WindApiClient _apiClient;

  OgcEdrWindDataSource({WindApiClient? apiClient})
      : _apiClient = apiClient ?? WindApiClient();

  @override
  bool get isSimulated => false;

  @override
  Future<WindData> getWind({
    required PositionData position,
    required AltitudeLevel altitude,
  }) async {
    final pressureLevel = _altitudeToPressure(altitude);
    final (u, v, _) = await _apiClient.fetchPointWind(
      lat: position.latitude,
      lng: position.longitude,
      pressureLevel: pressureLevel,
    );
    return WindData(
      uComponent: u,
      vComponent: v,
      altitude: altitude,
      timestamp: DateTime.now(),
    );
  }

  /// Maps AltitudeLevel enum to API pressure level.
  /// 0 = surface (special collection, no z param on Shyft).
  static int _altitudeToPressure(AltitudeLevel altitude) {
    return switch (altitude) {
      AltitudeLevel.surface => 0,
      AltitudeLevel.midLevel => 850,
      AltitudeLevel.jetStream => 300,
    };
  }
}
```

## API Response Parsing Details

### Shyft Position Query Response

Returns a `CoverageCollection` with **separate coverages** per parameter:

```json
{
  "type": "CoverageCollection",
  "coverages": [
    {
      "type": "Coverage",
      "ranges": {
        "u-component-of-wind": { "values": [3.97] }
      }
    },
    {
      "type": "Coverage",
      "ranges": {
        "v-component-of-wind": { "values": [1.18] }
      }
    }
  ]
}
```

Parser must iterate `coverages` to find U and V by parameter name.

### Folkweather Position Query Response

Returns a single `Coverage` with both params in `ranges`:

```json
{
  "type": "Coverage",
  "domain": {
    "axes": {
      "x": { "values": [237.5806] },
      "y": { "values": [37.7749] }
    }
  },
  "ranges": {
    "UGRD": { "values": [1.65] },
    "VGRD": { "values": [-3.47] }
  }
}
```

### Shyft Area Query (MultiPointSeries) -- for future Wind Dome

Uses `composite` axis with `[lng, lat, z]` tuples. Must extract unique x/y, sort, reindex to row-major grid. See research doc section "Shyft MultiPointSeries uses a composite axis".

### Folkweather Area Query -- for future Wind Dome

Standard `x`/`y` axes, row-major values. Longitude in 0-360 format needs conversion. Nulls in HRRR responses replaced with 0.0.

## Implementation Notes

### Decisions

1. **Point queries (not area queries) for WindDataSource** -- The `WindDataSource` interface returns a single `WindData`. Using position queries (one HTTP call, one U/V pair) is simpler and more efficient than fetching a grid and extracting the center. Area queries are implemented in `WindApiClient.fetchWindGrid()` for the future Wind Dome feature but are not called by `OgcEdrWindDataSource`.

2. **Constructor-injected http.Client** -- The project does not use mockito. Following the established pattern of manual test doubles, we inject `http.Client` in the constructor. Tests create a custom `http.Client` (from `package:http/testing.dart`) that returns canned JSON.

3. **WindField/WindVector in `lib/services/wind/`** -- These are implementation details of the wind service layer, not core domain models. They do not belong in `lib/core/models/` because they are not consumed by the provider graph or UI. Core domain uses `WindData` (Freezed). Service layer uses `WindField` (plain).

4. **API key as constant** -- The Shyft API key is stored as a compile-time constant in `wind_api_constants.dart`. For production, this should eventually move to a build-time environment variable or secure storage. For now, a constants file is the simplest approach and matches the research recommendation.

5. **300 hPa for jet stream (not 250)** -- Both APIs have 300 hPa. Shyft's 250 hPa is not consistently available. Using 300 hPa (~9km, close enough to 10.5km) provides reliable coverage on both APIs.

6. **Graceful degradation to zero wind** -- On network failure, the API client returns (0, 0). The `OgcEdrWindDataSource` constructs a valid `WindData` with zero components. Particles render but do not move. This is preferable to throwing an error or showing an error screen -- the camera feed and sky detection continue working.

7. **No new dependencies** -- `http: ^1.6.0` is already in pubspec.yaml. `package:http/testing.dart` provides `MockClient` for tests without adding dev_dependencies.

### Patterns

- Same service injection pattern as `MockWindDataSource` (constructor accepts optional dependencies)
- Same `@visibleForTesting`-style injection via constructor params
- Same cache decorator pattern as `CachedHorizonProvider`/`CachedWindDataSource`
- Same provider wiring pattern as other services in `service_providers.dart`

### Trade-offs

- **Point query vs. area query for AR view** -- Point query means we get the wind at one specific location. For the AR view (single `WindData`), this is correct. The area query with `WindField` is only needed for the future Wind Dome feature where particles move through a spatial wind field.

- **Single API call per altitude** -- Each `getWind()` call makes 1-2 HTTP requests (Shyft + optional Folkweather fallback). With caching (10 min TTL), this is at most 3 calls every 10 minutes (one per altitude level). The `stablePositionProvider` debounce (>100m) prevents GPS jitter from triggering redundant fetches.

- **Shyft CoverageCollection parsing is verbose** -- The U and V values come in separate Coverage objects. Parsing requires iterating through coverages. This is more complex than Folkweather's single-Coverage response, but worth it because Shyft has better altitude coverage.

## Non-Goals

- Real-time wind updates (push/WebSocket) -- TTL cache + pull on GPS change is sufficient
- Wind grid visualization in AR view -- Wind Dome is a separate future feature
- Offline wind data caching -- Wind changes too fast; stale data is misleading
- User-configurable API keys or endpoints
- Rate limiting logic -- Both APIs are free-tier with no observed rate limits
- Wind gust data -- `WindData.gustSpeed` exists but neither API provides it in position queries
- Animated transition when switching from mock to real wind -- Provider swap is seamless

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| Shyft API down | Folkweather fallback covers all altitude levels |
| Folkweather API down | Shyft is tried first; both-fail returns zero wind |
| API key revoked | Constants file makes key easy to rotate; app degrades gracefully |
| HTTP timeout on cellular | 12-second timeout; graceful degradation to zero wind |
| Folkweather 0-360 longitude | Explicit normalization in parser (tested) |
| Shyft 1000 hPa crash | Never requested; surface uses separate collection |
| HRRR coverage outside CONUS | Null values replaced with 0.0 |
| Shyft returns multiple timesteps | `datetime` param pins to nearest hour UTC |
| CachedWindDataSource not tested with real source | Integration tests verify the full chain |
| http.Client not closed | `ref.onDispose()` in provider closes the client |

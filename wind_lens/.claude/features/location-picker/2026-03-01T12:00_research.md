## Feature Context

**From user description:**
- Add a location pin button on the home screen that opens a map view
- User can update their longitude and latitude on the map
- This updates the wind data for that location
- Defaults to user's current GPS location
- Session-only persistence (resets to GPS on each app launch)

  // ...

**After change (watches effectivePositionProvider):**
```dart

  final position = ref.watch(effectivePositionProvider);
  if (position == null) throw StateError('No GPS fix yet');
  // ...
}
```

**Proposed locationOverrideProvider:**
```dart
@riverpod
class LocationOverride extends _$LocationOverride {
  @override
  PositionData? build() => null; // No override by default (use GPS)

  void set(PositionData position) {
    state = position;
  }

  void clear() {
    state = null;
  }
}
```

**Proposed effectivePositionProvider:**
```dart
@riverpod
PositionData? effectivePosition(EffectivePositionRef ref) {
  final override = ref.watch(locationOverrideProvider);
  if (override != null) return override;
  return ref.watch(stablePositionProvider);
}
```

## Open Questions

- [x] Q1: Where should the location pin button go on the home screen?
  - Resolution: In the `HomeTopBar`, as a third button alongside DOME and LIVE AR. A small map-pin icon or "LOC" text button matching the existing button styling.

- [x] Q2: Should the map screen use a bottom sheet or a full-screen page?
  - Resolution: Full-screen page with Navigator.push (consistent with AR view and Wind Dome navigation patterns).

- [x] Q3: Should wind data refetch immediately on every map tap, or only on confirm?
  - Resolution: Only on confirm. The user taps to position the pin, then taps a "Confirm" button to apply. This avoids unnecessary API calls during exploration.

- [x] Q4: How should the map show the current GPS position vs the selected override?
  - Resolution: Show a marker at the selected position (which defaults to GPS on open). When the user taps, the marker moves. A "Reset to GPS" button can snap back to GPS coordinates.

- [x] Q5: Should the `effectivePositionProvider` be a separate file or live in data_providers.dart?
  - Resolution: Separate file (`lib/core/providers/location_override_provider.dart`) for clarity. It contains both `locationOverrideProvider` and `effectivePositionProvider` since they are closely related.

- [x] Q6: What happens if GPS is not available when the map opens?
  - Resolution: Map defaults to (0, 0) or a reasonable fallback center. The user can still tap to select any location. This is edge-case behavior for MVP.

- [x] Q7: Should there be a visual indicator on the home screen when location is overridden (not GPS)?
  - Resolution: Yes -- the pin button could change color or show a small dot to indicate override is active. This is a nice-to-have for MVP but easy to add.

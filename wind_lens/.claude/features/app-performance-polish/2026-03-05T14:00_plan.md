## Splash Screen Architecture

### Provider Progress Mapping

The splash screen watches three independent async providers to compute a 0-100% progress value:

```dart
// Splash watches these providers:
effectivePositionProvider   -> null = waiting, non-null = GPS ready     (0-33%)
windDataProvider            -> AsyncLoading = waiting, hasValue = ready (33-66%)
horizonProfileProvider      -> AsyncLoading = waiting, hasValue = ready (66-100%)
```

Progress calculation:
- 0%: App just launched, sensors initializing
- 33%: GPS fix acquired (effectivePositionProvider non-null)
- 66%: Wind data loaded (windDataProvider has value)
- 100%: Horizon loaded (horizonProfileProvider has value or error -- we accept flat fallback)

Transition: When progress reaches 100% (or a timeout of 15s elapses), animate transition to HomeScreen using `Navigator.pushReplacement`.

### Key Design Decision: ConsumerWidget, NOT StatefulWidget

The splash screen should be a `ConsumerWidget` that watches the three providers. Each provider's state change triggers a rebuild, which updates the progress bar. No AnimationController needed -- the progress bar steps discretely at 33/66/100.

The transition to HomeScreen uses `WidgetsBinding.instance.addPostFrameCallback` to avoid navigating during build.

### Strict Data Gating (Task 1.7 -- NEW requirement)

User requirement: "that splash screen should only let me into the app when the terrain is for sure updated and everything else is fully loaded and won't lag once i'm in"

The splash screen must be STRICT about data readiness:

1. **No silent timeout entry.** The 15s timeout that auto-transitions to HomeScreen is removed. The splash ONLY transitions when all 3 providers have real values (GPS fix, wind data, horizon profile).

2. **60-second error timeout.** If data has not loaded within 60s, the splash shows an error message ("Unable to load data. Check your connection.") with a Retry button. It does NOT silently enter the app with incomplete data.

3. **Retry button.** Clears the error state, resets the 60s timer, and allows the providers to continue resolving. The providers themselves do not need to be reset -- they are already watching their dependencies and will resolve when network/GPS becomes available.

4. **2-second minimum display time preserved.** Even with cached/instant data, the splash shows for at least 2 seconds for a polished feel.

## Compass Heading Line Design

```dart
/// Vertical line tracking compass heading across terrain section.
///
/// Uses super(repaint: headingNotifier) so only this painter repaints
/// when heading changes -- no widget rebuild, no Riverpod rebuild.
class _HeadingLinePainter extends CustomPainter {
  final ValueNotifier<double> headingNotifier;

  _HeadingLinePainter({required this.headingNotifier})
      : super(repaint: headingNotifier);

  @override
  void paint(Canvas canvas, Size size) {
    final heading = headingNotifier.value;
    final x = (heading / 360.0) * size.width;
    final paint = Paint()
      ..color = const Color(0x40FFFFFF)  // 25% white
      ..strokeWidth = 1.0;
    canvas.drawLine(Offset(x, 0), Offset(x, size.height), paint);
  }

  @override
  bool shouldRepaint(_HeadingLinePainter old) => false;
}
```

Placed as a separate layer in the HomeTerrainSection Stack, between terrain (Layer 1) and altitude rail (Layer 3). This ensures the heading line repaints independently -- each CustomPaint in a Stack gets its own RenderObject.

## Location Picker Loading Screen Design

The loading screen solves the flutter_map cold-load freeze (Root Cause 1 from diagnosis). It uses `addPostFrameCallback` to defer the heavy screen load:

```
User taps location → CupertinoPageRoute → LocationPickerLoadingScreen
                                                  │
                                          Shows: dark scaffold + spinner
                                                  │
                                          addPostFrameCallback
                                                  │
                                          Navigator.pushReplacement → LocationPickerScreen
```

This gives the framework one frame to render the spinner before flutter_map initializes.

## Dome Changes

### Start Zoomed Out (E1)
In `wind_dome_screen.dart`, change initialization:
```dart
// Before:
double _camR = DomeConstants.camR;

// After:
```

Using 0.85 of camRMax (not full max) so the dome is visible but clearly zoomed out. Full camRMax = 90 RU makes the dome very small.

## Non-Goals

- **Provider graph restructuring** -- The existing graph stages naturally. The splash screen is a UX solution, not an architectural one.
- **Shimmer/skeleton animations** -- The progress bar is sufficient for startup. The location picker loading screen uses a simple spinner.
- **Disk caching for map tiles** -- CancellableNetworkTileProvider handles in-flight cancellation, which is the primary performance issue.
- **Deferred imports for flutter_map** -- The loading screen approach is simpler and achieves the same UX goal (no freeze).
- **Animated progress bar** -- Discrete steps at 33/66/100 are acceptable. Smooth animation would require a Ticker and adds complexity for minimal UX benefit.

## Implementation Notes

### Decisions
1. **Splash screen as separate route** (not an overlay): Cleaner separation, easier to test, natural Navigator transition.
2. **Loading screen for location picker** (not deferred imports): Deferred imports in Flutter are complex and not well-supported for non-web targets. A loading screen achieves the same UX.
3. **Keep home_particle_painter.dart**: Don't delete -- it may be useful later. Just remove the import from home_terrain_section.dart.
4. **Rewrite home_layer_toggles.dart** (not inline in home_screen.dart): Keep the file but replace contents with a simple static label widget. Minimizes diff in home_screen.dart.

### Patterns
- All GoogleFonts replacements follow: `GoogleFonts.dmMono(...)` -> `TextStyle(fontFamily: 'DM Mono', ...)`
- All GoogleFonts replacements follow: `GoogleFonts.bebasNeue(...)` -> `TextStyle(fontFamily: 'Bebas Neue', ...)`
- CupertinoPageRoute requires `import 'package:flutter/cupertino.dart'`

### Trade-offs
- The splash screen is strict -- users on slow networks will see an error message + retry after 60s instead of entering the app with incomplete data. This is the user's explicit request: "only let me into the app when... everything else is fully loaded."
- If GPS permissions are denied or network is unavailable, the user will be stuck on the splash screen until they fix the issue and tap Retry. This is intentional -- entering the app without data would cause lag and "--" placeholders.
- Removing home screen particles means the terrain section is purely static (until heading line is added). This is the user's explicit request -- "GPU waste".
